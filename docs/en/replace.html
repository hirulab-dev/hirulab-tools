Regex Replacement Preview

See what a regex replacement will do before you run it. Every $1 and $& in the replacement template is spelled out one at a time, and each piece of the result is traced back to the token that produced it. JavaScript replacement strings have several forms that quietly turn into something else without raising an error. Naming those is the point of this page.

This page makes no network requests at all. Parsing and replacing both happen inside your browser. Once loaded, it works in airplane mode. Nothing you type is sent anywhere.

    Replacement forms that change meaning without raising an error
    
      
      
    • If no group matches $1, there is no error — the characters $1
        are emitted verbatim. This is what bites you after deleting one capture group.
      • 
      
    • $<name> is only special if the pattern has at least one named group.
        Given that, a misspelled name is not an error — it becomes the empty string and disappears.
        In a pattern with no named groups at all, $<name> comes out as plain text instead.
      • 
      
    • \1 is not a back-reference. In a JavaScript replacement string it is
        just 1 (the \ is consumed by the string literal).
        This is the habit that carries over from sed and Python.
      • 
      
    • ${1} is not special either. It comes out as ${1}.
      • 
      
    • $` and $' mean the text before and after the match, but
        both refer to the original string — not to the half-replaced one.
      • 
      
    • Without g, only the first match is replaced. No error is raised.
      • 
      
    • Zero-length matches (from x* and friends) land between characters:
        "abc".replace(/x*/g, "-") gives -a-b-c-.
      • 
    
    
  
    

  
    
    How this page is built, and how it is checked
    
      
      
    • The pattern parser is the same one used by
        the railroad diagram tool and
        the "why doesn't my regex match" tool.
        A script checks that all three copies are byte-identical before anything is published.
      • 
      
    • The template expansion is written from scratch here.
        String.prototype.replace only hands back the finished string, so tracing
        each character to the token that produced it means assembling the result yourself.
      • 
      
    • Anything written from scratch can drift. So every keystroke, the assembled result is
        compared against the browser's own replace and the outcome is shown in
        the self-check box. If they disagree, the browser is the one to trust.
      • 
      
    • A set of built-in cases runs at the same time — including whatever is on screen right now.
