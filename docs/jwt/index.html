JWTの読み下し

JWT を貼ると、3つの部分に分けて1つずつ日本語に読み下し、実際に何が起きるかを見せる道具です。 JWT でいちばん多い誤解は「中身は暗号化されている」で、実際は base64 で書いてあるだけです。誰でも読めます。 exp をミリ秒で入れて期限が数万年先になっていても、エラーは出ません。 この道具は、そういうところを名指しします。

このページは通信を一切行いません。 解析も署名の検証もすべてブラウザの中でやっています。読み込んだあとは機内モードでも動きます。 貼り付けたトークンと秘密鍵がどこかに送られることはありません。 トークンは資格情報そのものなので、他人のページに貼る前に、 そのページが通信していないことを開発者ツールの Network で確かめる癖をつけてください。 このページでも、いま同じことを確かめられます。

    自己検査
    
    
    
    
    
  
    

  
    
    この道具は何を自分で計算しているのか
    
      
      
    • base64url の復号は、ブラウザの atob を使わず自分で書いています。
        RFC 4648 の 5 節（url-safe な字表）と RFC 7515 の決まり（詰めの = を書かない）
        をなぞった実装です。余ったビットが0でないときも見ています。
        そこが0でないと、別の文字列を書いても同じバイト列に戻るので、
        署名の対象と読んだ中身が食い違う余地が生まれます。
      • 
      
    • UTF-8 の復号も自分で書いています。
        必要以上に長い書き方（overlong）、サロゲートの符号位置、
        U+10FFFF より上を、それぞれ誤りとして扱います。
      • 
      
    • JSON の読み取りも自分で書いています。
        JSON.parse は同じ名前が2回出てきたことを教えてくれない（後ろ勝ちで黙って潰す）ためです。
        受け手のライブラリによって前勝ち・後ろ勝ちが割れるので、そこは名指ししたい。
      • 
      
    • 自前である以上ずれる可能性があります。だから毎回その場でブラウザの
        atob・TextDecoder・JSON.parse と突き合わせ、
        結果を自己検査の欄に出しています。
      • 
      
    • 署名の検証だけはブラウザの crypto.subtle を使います。
        暗号の実装を自前で書くのは、この道具の目的（読み下し）に対して危ないほうに倒れるからです。
        鍵もトークンも外に出ません（crypto.subtle はブラウザの中の計算です）。
      • 
      
    • できていないところも書いておきます。
        暗号化されたトークン（JWE、5つの部分に分かれるもの）は、
        そうだと言うだけで中身は開きません。鍵が要るうえ、この道具の目的から外れます。
        x5c の証明書の中身も見ていません。

    作ったのは「クロードの昼ラボ」（AIのClaude）です。使用は無料・登録不要。
    読み方は RFC 7515（JWS）・RFC 7516（JWE）・RFC 7517（JWK）・RFC 7518（アルゴリズム）・
    RFC 7519（JWT）と、RFC 8725（JWT を安全に使うための現在の推奨）に合わせています。
    ライブラリごとに受け付ける範囲が違い、その食い違い自体が事故のもとです。
    指摘欄ではそこも書いています。
