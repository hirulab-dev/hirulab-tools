タイムゾーン変換

日時を入れると、選んだ都市の現地時刻をまとめて並べます。 24時間の重なり表から会議の候補時間が見つかり、 各都市が次に時差を変える日も分かります。 夏時間の切替で入力した時刻が存在しないときや 1日に2回あるときは、黙ってずらさずにそう伝えます。

このページは通信を一切行いません。 時差のデータはブラウザ自身が持っているもの（IANAタイムゾーンデータベース）を読んでいます。 読み込んだあとは機内モードでも動きます。入力した予定がどこかに送られることはありません。

このブラウザの時差データは新しいか

時差の規則は毎年どこかの国が変えます。ブラウザが内蔵しているデータが古ければ、 このページの答えもその分だけ古くなります。最近変わったところを狙って3つ確かめます （基準は IANA タイムゾーンデータベース 2026c。2026-08-22 に照合した内容です）。

夏時間まわりで何が起きるのか（このページが指摘すること）
  • 存在しない時刻がある: 夏時間が始まる日、時計は 2:00 から 3:00 へ飛びます。 その日の 2:30 はこの世に存在しません。多くの変換サイトは黙って 3:30 に読み替えますが、 このページは「存在しない」と表示して、前後どちらに寄せるかを見せます。
  • 1日に2回ある時刻がある: 夏時間が終わる日、時計は 2:00 から 1:00 へ戻ります。 その日の 1:30 は2回来ます。どちらの 1:30 かで、他都市の時刻は1時間ずれます。 このページは両方を出します。
  • 時差は固定ではない: 日本とニューヨークの差は 13時間か14時間かのどちらかで、 年に4回入れ替わります（切り替わる日が日米でずれるため）。 「毎週この時間」で決めた定例会議は、年に数回、片方だけ1時間ずれます。 表の「次に時差が変わる日」がその日です。
  • 1時間とは限らない: オーストラリアのロードハウ島は30分しか動きません。 インドは +5:30、ネパールは +5:45、ニュージーランドのチャタム諸島は +12:45 です。
  • 南半球は逆: シドニーやサンパウロの夏は日本の冬です。切替の向きも逆になります。
このページの作り（何を信じて、何を信じていないか）
  • 時差のデータはブラウザの中にあります。どのブラウザも IANA タイムゾーンデータベースを 内蔵しているので、通信せずに「その都市のその瞬間の時差」が引けます （Intl.DateTimeFormat 経由）。このページは自前の時差表を持っていません。 持つと更新のたびに嘘になるからです。
  • 切替日は探して見つけています。ブラウザは「いつ切り替わるか」を直接教えてくれないので、 1時間ずつ時差を見比べて変わり目を挟み込み、そこから二分探索で1秒まで詰めています。
  • 略称（JST・PDT など）は表示していません。環境によって GMT+9 になったり JST になったり割れるうえ、CST のように複数の国で同じ略称が使われるものがあります。 このページはオフセット（UTC+09:00）を正としています。
  • ブラウザのデータが古い可能性は残ります。各国の夏時間の廃止・変更は毎年あり、 反映はブラウザの更新に依存します。上の「このブラウザの時差データは新しいか」が その簡易チェックです。
  • 検証: このページの計算部分を取り出して、Python の zoneinfo （別のタイムゾーンデータ）と突き合わせています。時差・現地時刻・切替日時・ 「存在しない／2回ある」の判定を、72の都市 × 2015〜2030年で1件ずつ比較しました。 その過程で、照合に使ったブラウザのほうが2か所古いことが分かりました （バンクーバーとカサブランカ）。上の鮮度チェックは、その2か所をそのまま使っています。
